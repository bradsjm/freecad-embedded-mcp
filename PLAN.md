# Embedded MCP v2 — Refined Implementation Plan

## Context

Replace the separate MCP client application and XML-RPC bridge in `freecad-mcp/` with a native Streamable HTTP server embedded in the FreeCAD add-on. Target MCP `2026-07-28` exclusively and FreeCAD `1.1.3 <= version < 1.2`, on branch `v2.0-embedded-mcp`, with no compatibility server or CLI. Preserve the requested document, modeling, geometry, parameter, export, view, FEM and script operations; simplify execution and make consent, cancellation and migration behavior explicit.

## Approach

### 1. Establish contracts before the atomic cutover

Work from repository root `freecad-mcp/`. Create `v2.0-embedded-mcp` from `main` when absent; reuse it if already present, never reset unrelated changes. Implement steps 2–6 under new `addon/FreeCADMCP/mcp_server/` while the legacy entrypoint remains intact. Step 7 switches imports and removes legacy implementation together; never move a live dependency away before its callers switch. Existing tests must remain runnable between these boundaries.

Use Python 3.11-compatible syntax: live FreeCAD 1.1.3 was inspected and embeds Python 3.11.14. The original Python >=3.12 baseline is incorrect. Stdlib-only means no newly installed runtime packages; Qt, FreeCAD, OCC, FEM and VTK supplied by FreeCAD remain available.

Keep module responsibilities concrete:
- `protocol.py`: envelope validation, result/error builders, consent signing and the finite schemas used by this server.
- `http_server.py`: authenticated HTTP/SSE transport; no FreeCAD imports.
- `tasks.py`: locked task records and operation lifecycle, no FreeCAD imports.
- `subscriptions.py`: subscription filters and bounded outgoing queues, no GUI/network writes in observer callbacks.
- `server.py`: startup, tool registration, dispatch, observer registration and shutdown. Put environment checks and operation orchestration here; do not add separate startup/context/runner/capability abstraction layers.
- `settings.py`, `gui_dispatch.py`, `dispatch_health.py`, `object_validation.py`: reuse the existing corresponding `rpc_server/` implementations, with changes specified below. Extract only IP parsing from `ip_filter.py`; do not import its XML-RPC server.
- `tools/documents.py`, `objects.py`, `geometry.py`, `parameters.py`, `export.py`, `view.py`, `fem.py`, `script.py`: direct tool implementations. Capability discovery belongs in `server.py`.

No equivalent native protocol/HTTP/task/consent implementation exists in the current repository. Reuse dispatcher mechanics, validation behavior, property conversion and screenshot logic rather than retaining a second public API.

### 2. Implement the exact released wire contract

Authoritative sources: [core specification](https://modelcontextprotocol.io/specification/2026-07-28), [MRTR](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr), [subscriptions](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/subscriptions), and the released `schema/2026-07-28/schema.ts` in `modelcontextprotocol/specification`; Tasks uses `schema/2026-07-28/schema.ts` and `specification/2026-07-28/tasks.md` in `modelcontextprotocol/ext-tasks`. Copy the selected wire fields from those schemas, not an older SDK's initialize/session model.

Implement `validate_request(message, headers)`, `complete_result(payload)`, `tool_result(payload, *, is_error=False)`, and `input_required_result(input_requests, request_state)` in `protocol.py`. Validate JSON-RPC 2.0, string/integer IDs (not booleans), method, object params and required request `_meta`: `io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/clientInfo` with string name/version, and object `io.modelcontextprotocol/clientCapabilities`. Missing metadata is invalid params; missing/malformed/mismatched required routing headers is `-32020`. After envelope validation, header/body mismatch precedes version negotiation. Matching unsupported versions return `-32022` with `data:{supported:["2026-07-28"],requested:<version>}`, including discovery; do not invent a discovery version exemption.

All results carry `resultType` and `_meta["io.modelcontextprotocol/serverInfo"]={name:"freecad-mcp-addon",version:"2.0.0"}`. Use `-32700` parse error, `-32600` malformed envelope, `-32601` unknown method/tool, `-32602` invalid parameters, `-32603` unexpected protocol infrastructure error, `-32020` header mismatch, `-32021` missing client capability with `data.requiredCapabilities`, and `-32022` unsupported version. No arbitrary positive application-error namespace: FreeCAD execution failures are complete tool results with `isError:true`, concise text and structured `{error:{code,message,details}}`. Codes include `DOCUMENT_NOT_FOUND`, `OBJECT_NOT_FOUND`, `VALIDATION_FAILED`, `GUI_DISPATCH_FAILED`, `CONSENT_DENIED`, `PATH_NOT_ALLOWED`, `UNSUPPORTED_VIEW`, `SOLVER_FAILED`. Preserve captured diagnostics rather than returning only a string.

Use explicit finite input schemas with `additionalProperties:false`, bounds, enums, required fields and reusable local definitions. Implement validators only for schema constructs actually emitted; reject unsupported constructs during registration rather than silently skipping them. No network `$ref` resolution or general-purpose schema engine. Unknown extension metadata is not rejected merely because the server does not use it. Validate tool output against its registered structured schema before serialization; disallow NaN/infinity. Normal structured tool results include both `structuredContent` and its JSON text representation; `capture_view` returns PNG image content.

Register `server/discover`, `tools/list`, `tools/call`, `tasks/get`, `tasks/update`, `tasks/cancel`, `subscriptions/listen`, and the document resource methods below. Do not add initialize, protocol sessions, a GET SSE endpoint, task-result aliases or notifications/cancelled for HTTP. Discovery and tools/list are GUI-independent after startup. Discovery advertises `supportedVersions:["2026-07-28"]`, tools, document resources and `extensions:{"io.modelcontextprotocol/tasks":{}}`.

Caching hints apply to complete discovery/list/resource responses, not universally to tool execution results or MRTR. Use `ttlMs:3600000,cacheScope:"public"` for protocol discovery and static tool definitions; `ttlMs:0,cacheScope:"private"` for live document resources. Machine-specific capability data stays private.

### 3. Authenticate transport and centralize consent

Use `ThreadingHTTPServer` with daemon request threads on `127.0.0.1`, configurable port default `9876`, sole RPC endpoint `POST /mcp`. Require bearer authentication on every request, constant-time token comparison, valid Content-Type JSON and Accept supporting JSON plus SSE. Require `MCP-Protocol-Version`, `Mcp-Method`, and method-specific `Mcp-Name`, including task IDs for task methods; validate released Base64 sentinel header encoding before comparing values. Validate any emitted `Mcp-Param-*` against its body source. Reject duplicate routing/auth/content-length headers, transfer-encoding request bodies, oversized bodies (>8 MiB), and malformed lengths before dispatch. Set a 10-second request-read timeout. Return 401 missing/bad token, 403 disallowed peer/Origin/Host, 413 oversized body, 415 unsupported media, 406 unacceptable response types. Authenticated unknown paths/methods return 404 with `-32601`; no request ID is fabricated when unavailable. Valid notifications receive empty 202 and must never execute a request-only tool operation.

Accept Host only for the configured loopback endpoint (`127.0.0.1` or `localhost`, actual port); Origin absent is allowed, present must match one of those HTTP origins. Do not add CORS or remote binding. Retain validated `allowed_ips` as an additional peer restriction, not a remote-enablement switch. Malformed settings fail startup rather than silently weakening access restrictions.

JSON responses have explicit Content-Length. SSE uses HTTP/1.1 chunked framing, `Content-Type:text/event-stream`, `Cache-Control:no-cache`, `X-Accel-Buffering:no`; flush each `data: <JSON>\n\n` event, comment keepalive every 15 seconds, finish with a zero chunk after the final result. A stream writer is owned by its request thread, never a GUI callback. Send progress only when the original `_meta.progressToken` exists; logs only when requested logLevel permits them. Stop all request-scoped notifications after its final response or disconnect.

Settings persistence remains under `App.getUserAppDataDir()` using the existing settings filename. New schema: `port=9876`, generated `token=secrets.token_urlsafe(32)`, `auto_start=false`, `allowed_ips="127.0.0.1"`, `allowed_roots=[expanded home directory]`. Ignore/remove legacy `remote_enabled` and `auto_start_rpc`; do not interpret old automatic RPC startup as consent to start v2. Write secrets atomically with user-only permissions; fail closed on unreadable/invalid settings. Do not print tokens in logs. No persisted consent key: generate a random in-memory HMAC-SHA256 key on each server start.

Every path-taking tool canonicalizes with realpath and requires commonpath containment in an allowed root. Resolve destination parents and recheck immediately before publishing. `run_script` executes arbitrary code with the FreeCAD user's privileges and is explicitly not sandboxed by allowed_roots; the bearer token is full local code-execution authority. Do not describe these path checks as a sandbox.

Consent preflight happens before creating a task or mutating anything. Require MRTR form elicitation for untrusted opens, dirty close/reload, and overwriting any existing destination. The form key is `confirm`, method `elicitation/create`, mode `form`, schema requiring boolean `confirmed`; only `action:"accept"` plus `content.confirmed:true` permits execution. Capability absent returns `-32021` with required form-elicitation capability. Decline/cancel returns `CONSENT_DENIED` without effects. Missing necessary response repeats the challenge.

Sign requestState containing principal fingerprint, expiry (5 minutes), random nonce, method/tool/arguments digest and target fingerprint (file identity/size/mtime or document generation). Verify signature, expiry, principal and args before interpreting inputResponses; reject tampering. Keep consumed nonces in memory until expiry and consume under a lock before scheduling, preventing duplicate destructive execution. If target changed since consent, request new consent. No lock/transaction remains open while waiting for the user. Retries use protocol `params.requestState` and `params.inputResponses`, not tool arguments.

### 4. Use one execution lifecycle for blocking calls and tasks

Reuse the existing Qt-signal queue, per-call result isolation, reentrancy guard, popup/drag/modal deferral and `DispatchHealth` stuck detection in `gui_dispatch.py`. Replace the mixed string/dict dispatch outcome with one internal structured outcome carrying value, stdout, stderr, traceback and error. Update both dispatcher tests and every caller in the atomic cutover. Add cooperative cancellation and eventual completion explicitly: `submit_to_gui(fn, *, operation_name, cancel_event, on_finished)` returns a Future; `dispatch_to_gui` becomes its blocking wrapper for internal callers. A cancelled queued job never enters FreeCAD; a running job is not declared stopped merely because a waiter timed out. `on_finished` runs exactly once after actual completion, including exceptions. Preserve existing stuck fail-fast until the running callable returns. No HTTP thread reads FreeCAD objects, even for lists.

`TaskStore` exposes `create(operation,args)`, `get(task_id)`, `complete(task_id,result)`, `fail(task_id,error)`, `request_cancel(task_id)`; protect transitions under one lock. Use fixed task eligibility: run_script, run_fem, export and measure. If the client declares the Tasks extension, create a record before sending the flat `resultType:"task"` result. Otherwise execute through the same operation lifecycle and return a complete result over request SSE. Do not use duration heuristics or separate fire-and-forget execution.

Task statuses are `working|input_required|completed|failed|cancelled`; createdAt/lastUpdatedAt are UTC timestamps, initial ttlMs=3600000, pollIntervalMs=500. CreateTaskResult and tasks/get are flat; tasks/get has resultType complete and terminal `result` containing the original tool result, or `error` for JSON-RPC failure. A tool failure with isError:true is completed, not failed. Every task method and task subscription requires the extension capability on that request, otherwise -32021. Generate unguessable IDs and bind records to the authenticated principal. Unknown/expired task IDs return -32602. tasks/update accepts `{taskId,inputResponses}`, ignores keys not outstanding and returns empty complete acknowledgement; all tools elicit before task creation, so this release has no outstanding task input keys. tasks/cancel accepts `{taskId}` and returns empty complete acknowledgement, including already-terminal tasks without changing them. Task notifications use notifications/tasks with full DetailedTask fields; never send progress/log notifications for detached tasks.

Cancellation sets an event. Queued work becomes cancelled without execution. Running Python/OCC code remains working with a cancellation-requested status message until a safe boundary; do not inject exceptions into Python threads or kill solver processes. A boundary that actually abandons remaining work may finalize cancelled, stating any effects already made. If work finishes before cancellation takes effect, finalize completed with its real result and diagnostics, not a false cancelled state. Never overwrite a terminal state. Blocking SSE disconnect requests cancellation of that operation only. Closing the response that created a detached task, or its status subscription, does not cancel the task; detached cancellation requires tasks/cancel.

TTL is measured from createdAt, not lastUpdatedAt. Keep working records, extending their advertised ttlMs on the service tick before expiry; at terminal transition set ttlMs to elapsed-since-creation plus 3600000. Expire terminal records at createdAt+ttlMs. Sweep on TaskStore access and the existing server service tick; no extra TTL thread. Cap retained tasks at 1024 and accepted nonterminal operations at 32; reject new work with a busy tool error rather than evict running work. Protocol discovery/list/task status remain responsive when GUI work is stuck.

Subscription registry uses connection-scoped identity plus JSON-RPC subscription ID, not a global ID alone (different clients can use id=1). First event is notifications/subscriptions/acknowledged with the honored filter and `_meta["io.modelcontextprotocol/subscriptionId"]`; stamp that metadata on every event and final result. Honor requested notification kinds only, including Tasks taskIds. Each connection has a 256-event queue; overflow closes it rather than blocking the GUI or silently losing events. Shutdown sends a final complete subscription response where transport remains writable.

Expose native document events through actual resources, not fabricated tools/list_changed events: resources/list returns one `freecad://documents` JSON resource; resources/read for it returns compact `{documents:[{name,label,fileName,objectCount}]}`. Register one plain Python document observer (no invented FreeCAD superclass), implementing slotCreatedDocument, slotDeletedDocument, slotActivateDocument, slotRecomputedDocument and object/change/save slots needed to increment per-document generations. Emit notifications/resources/updated for this URI only to its subscribers. This preserves document events without custom notification extensions. Remove observer at shutdown; do not add a one-second polling fallback.

### 5. Implement the deterministic tool surface

Register the following **17**, not 15, tools in this order. Input defaults below are server-applied; return actual sanitized Name values, never echo requested names as identity. Missing documents/objects produce the corresponding tool error. All mutations and serialization occur on the GUI thread.

1. `discover_capabilities()`: private snapshot of FreeCAD/OCC versions, workbenches, supportedTypes sample, exporter availability, FEM availability and paths from actual FreeCAD path getters. App.ApplicationDirectories is not a directory mapping: observed members are migration/version helpers. Include GUI health separately without waiting for GUI dispatch.
2. `new_document(name)`: create and return name/label/objectCount.
3. `open_document(path, untrusted=true)`: consent before opening untrusted FCStd; validate path and extension, return actual identity. FreeCAD may leave a document after load failure; remove only the newly created failed-open document, never existing documents. Consent does not certify a file safe.
4. `save_document(document, path?)`: no path uses existing FileName; unsaved document without path is an actionable error. Explicit save-as to an existing target requires consent; saving to the document's own current file is normal save behavior.
5. `close_document(document)`: dirty or unsaved nonempty document requires consent; close only that document.
6. `reload_document(document)`: require a saved existing path and dirty-discard consent; remember path/name, close and reopen, return actual reopened name/label/count. Report if reopening failed after close; do not claim rollback. Confirm dirty-state API in step 6's runtime probe; fallback is conservative consent on every close/reload, never skip consent based on an unknown API.
7. `inspect_objects(document, cursor?, property_filter?, detail="compact", limit=100)`: sorted by Name; cap limit at 500. Compact name/label/TypeId/state/placement/bounds/shape validity/solid count/Body tip/link identities. Full detail adds requested properties; unsupported values get a typed unavailable marker, never recursive stringification of document objects. Opaque cursor binds document generation, last Name and filters; stale cursor returns a restart-pagination error. Empty document returns an empty page.
8. `create_object(document, type, name, properties?, expected_solids?)`: validate types against document.supportedTypes and explicit factory mapping for FEM types, not guessed factory names. Preserve generic Part/App object creation; support modern FEM analysis/solver/material factories explicitly. Return actual identity and post-recompute validation. For PartDesign::Body, explicit expected_solids permits multisolid contracts; shapeless containers/sketches are not invalid merely for lacking a solid.
9. `edit_object(document, object, properties, expected_solids?)`: prevalidate every property name/type/reference; reject read-only/unknown properties before applying. Preserve existing vector, placement, color, ViewObject and reference conversions. Canonical links use `{object:<Name>,subelement:<name>}`; no legacy Object/Face/array aliases. Resolve topology tokens freshly for the current document; numeric Face/Edge selectors are not accepted as durable geometry selectors. Expose FuzzyTolerance when actually present on boolean features, no synthetic property.
10. `delete_object(document, object)`: refuse an object with dependents rather than silently cascading; otherwise remove and recompute within the transaction contract.
11. `validate_geometry(document, objects, expected_solids?, expected_bounds?, bounds_tolerance=0.000001)`: per-object state/isValid plus shape validity, solid count, volume, bounds, shape.check diagnostics and shape.getTolerance(1) maximum tolerance. Require positive volume for intended solids; distinguish valid non-solids. expected_bounds is a map from object Name to six finite mm coordinates; compare each coordinate using the nonnegative bounds_tolerance. Without expected_bounds, return measured bounds without a bounds-comparison verdict. Do not repair geometry silently.
12. `measure(document, a, mode, b?, plane?)`: modes distance/interference/section/faces. a/b select an object name or `{object,role:"face"|"edge",box:[xmin,ymin,zmin,xmax,ymax,zmax]}`; match subshape bounding boxes within 1e-6 mm, require exactly one, report candidates on ambiguity. Distance uses distToShape, interference uses common.Volume, section uses either z or normal+point and returns bounded wire/curve/radius summaries, faces returns areas and sampled normals. Reject missing b/plane for modes that require it; preserve mm/mm²/mm³ units.
   For selected subshapes and faces-mode output, return a canonical reference `{object,subelement}` whose subelement is an opaque HMAC-signed token containing document identity/generation, object Name, role and resolved index. Reference consumers verify it, resolve the current subshape and reject stale generation; they never accept a caller-supplied Face7/Edge7 as a durable selector. Empty subelement denotes the whole object. This uses the existing server signing key, not another registry.
13. `edit_parameters(document, object, expressions={}, rename={}, add=[])`: validate all names/types first; use setExpression, renameProperty and addProperty, then recompute and apply the same mutation gate. Rename only dynamic properties; reject collisions and invalid expression references with rollback.
14. `export(document, objects, format, path, linear_deflection=0.03, angular_deflection=0.12, bed_align=false)`: STL/STEP/3MF/FCStd details below.
15. `capture_view(document, focus_object, view_name, width?, height?)`: explicit GUI document/view; views Isometric/Front/Top/Right/Back/Left/Bottom/Dimetric/Trimetric. Use current viewport dimensions when omitted, clamp longest edge to 1024 only for omitted sizes; explicit positive sizes limited to 4096. Missing focus is OBJECT_NOT_FOUND, never fitAll. Preserve selection and active document in finally; use five-argument saveImage(path,w,h,"Current","Framebuffer") only, return PNG and remove only its temporary capture file.
16. `run_fem(document, analysis, timeout_s=600)`: modern pipeline flow below.
17. `run_script(code, session_id="default", timeout_s=90)`: per-explicit-session namespace seeded with FreeCAD/App/Gui; exec on GUI thread and capture stdout/stderr/traceback even on error. No untracked async path. Bound stored namespaces to 32; reject new sessions when full rather than evict live state. Timeout requests cooperative cancellation and reports the uninterruptible limitation. Namespaces last for the server lifetime, not a protocol session. Generic scripting remains the escape hatch for unsupported modeling/parts-library workflows; do not reintroduce a separate client or parts-library public API.

Mutation gate: reuse object_validation's rejection of Invalid/Error/Touched and object.isValid, extending shape checks without breaking valid shapeless objects. Default one-solid contract only for produced volumetric geometry, not App groups, spreadsheets, sketches or empty Bodies. Explicit expected_solids overrides it. Validate all affected recomputed dependents, not only the directly edited object. Reject an already active transaction using App.getActiveTransaction and doc.HasPendingTransaction before opening an MCP transaction; never commit the user's transaction. Preserve UndoMode, enable only for the operation if needed, openTransaction/commitTransaction on success and abortTransaction on assignment/recompute/validation failure, restoring UndoMode in finally. Failed atomic edits report applied=[] and failed reasons; never claim a partial assignment survived a successful rollback. Report rollback failure separately.

### 6. Prove export, GUI and FEM integration before switching entrypoints

Use one disposable document and a temporary directory inside the configured home root for runtime API checks. Never probe mutation APIs against existing user documents. Confirm transaction rollback (including dependent recompute), modern FEM completion, five-argument capture, mesh/STEP round trips, and dirty-state detection. Installed source and earlier read-only runtime inspection confirmed openTransaction/commitTransaction/abortTransaction, HasPendingTransaction, getActiveTransaction, renameProperty, shape.getTolerance(1), shape.check and Fem.frdToVTK. Dirty-state API and asynchronous FEM completion have not been live-tested: **unverified — confirm first** with the disposable fixture. For dirty-state detection inspect the explicit GUI document's modified state; if unavailable, require consent for every close/reload as specified above.

Export accepts a nonempty object list for stl/step/3mf; for fcstd require objects=[] to mean the entire native document, and reject meshing/bed-align options. This avoids pretending a shape copy preserves parametric history. Use doc.saveCopy for FCStd, retaining original FileName, placements and dirty state; verify by reopening a hidden temporary document and compare object identities/count, then close only that temporary document.

For mesh/STEP exports, resolve selected objects to placed shape copies, validate intended solids, and apply one collective translation of minimum Z to zero when bed_align=true. Do not individually align parts or change the assembly. Mesh with MeshPart.meshFromShape using the supplied positive finite deflections, combine meshes and write STL or 3MF; Mesh.Mesh.write supports Format="3MF" in the inspected FreeCAD source. STEP writes the copied shapes through Part export, with only temporary holders if its API requires document objects. Read mesh files back and return isSolid, CountFacets and bounds; read STEP back and return isValid, solid count, volume and bounds. A failed readback is an export error, not success with a warning.

Write to a sibling temporary destination with the intended extension, verify there, then publish. For a previously nonexistent destination, use exclusive no-clobber publication; if a file appears meanwhile, fail with a fresh-consent-required error rather than overwrite it. For authorized replacement recheck the approved target fingerprint and use os.replace. If the fingerprint changed after a task was created, finish with a tool error asking the client to retry the original operation; do not create mid-task consent state. Remove only this operation's temporary files. Native multi-file export artifacts must remain together; 3MF is one archive, FCStd is one native document. Permission/full-disk/exporter errors preserve the old destination.
For exclusive new-file publication use os.link(staged_path,destination) then unlink the staged name, with both in the same destination directory. If the filesystem does not support hard links, fail with an actionable export error; never replace it with a racy existence-check plus overwrite. Ordinary save_document uses native save/saveAs rather than staged FCStd copying because it intentionally changes the document's save identity.

FEM uses `ObjectsFem.makeSolverCalculiX`, not `makeSolverCalculiXCcxTools`. Inspected source: modern solver proxy Type is `Fem::SolverCalculiX`; `femsolver.calculix.calculixtools.CalculiXTools` runs QProcess and loads `Fem::FemPostPipeline` through Fem.frdToVTK. The old CcxTools pipeline is not a compatible alias. For an existing analysis: require one modern solver, or create it when no solver exists; if only a legacy solver or multiple solvers exist, return a clear unsupported/ambiguous-solver error without deleting or converting them. Require mesh/material/constraints through the native analysis checks before running.

On GUI thread instantiate CalculiXTools(solver), assign a unique working directory under an allowed root before construction, call prepare(), then compute(); retain the tool and QProcess until completion. Do not call run(blocking=True) or waitForFinished on the GUI thread. ObjectTools connects process.finished to update_properties on successful exit; arrange the MCP completion callback after native result loading and catch/report conversion/loading failures. Handle failed-to-start and nonzero exits, capturing stdout/stderr and working_dir. Timeout/cancel marks cancellation requested but does not kill the solver. Lock the analysis against another MCP solve and reject mutations/close/reload on that document while solving; keep no document transaction open across QProcess execution. If arbitrary run_script is requested during an active solve, reject it as busy since its target documents cannot be inferred. User edits/closure invalidate the operation; validate document identity/generation before loading/reporting results.
Implement the FEM lifecycle as a small local CalculiXTools subclass overriding update_properties: validate document identity/generation before calling super().update_properties(), catch its exceptions into the operation result, and finalize success only after pipeline extraction. Connect failed-to-start/nonzero-exit handlers to the same exactly-once finalizer. Record generation after prepare and before compute, excluding this operation's own expected result-load events. This intercepts native loading before it can mutate a document invalidated by user activity; do not merely check after the base signal handler has already loaded results.

Locate the newly created or updated pipeline through solver.Results and isDerivedFrom("Fem::FemPostPipeline"); never scan legacy result objects for vonMises. Read pipeline.Data as its VTK multiblock dataset: iterate nonempty leaf grids, return per-block point/cell counts and finite scalar/vector-magnitude min/max ranges, plus aggregate counts explicitly labeled as sums (not globally deduplicated nodes). Return pipeline name, working_dir, and the generated .vtm path as vtk_path together with its referenced .vtu files; do not rename it to .vtk. If conversion or VTK support is absent, advertise run_fem unavailable and fail before launching rather than silently using old results. Missing CalculiX executable is an actionable tool error; do not auto-install it. Include has_frd_to_vtk from Fem, not femtools.

For operation deadlines, server service_actions checks monotonic deadlines independently of GUI. Default ordinary GUI deadline is 60 seconds; export/measure 600 seconds; script/FEM use timeout_s constrained to 1..3600. A deadline cannot preempt OCC/Python. Blocking request may return a timeout tool error stating work still running; detached task retains truthful working state until it actually ends. FreeCAD objects and late callbacks stay alive until completion; no server restart may create a competing dispatcher while old GUI work remains active.

### 7. Switch the add-on and distribution atomically

Add `mcp_server/commands.py` and switch both imports in `InitGui.py`, workbench toolbar/menu and `_auto_start_mcp` to `mcp_server.server`. Register Start_MCP_Server, Stop_MCP_Server, Toggle_Auto_Start and Show_Auth_Token. The token dialog displays endpoint and token with an explicit copy button; it is local UI only. Remove Toggle_Remote_Connections and Configure_Allowed_IPs. Startup checks version tuple `(1,1,patch>=3)` before binding or observer registration, captures static capabilities on GUI thread, initializes the dispatcher once, and then starts HTTP. Duplicate start returns existing state; bind failure unwinds observers/waker and never reports running. Stop closes acceptance and subscription streams, cancels queued jobs, requests cancellation of running operations and returns without joining a stuck GUI call. Keep finalizer ownership until actual completion, then dispose Qt objects on their owning thread. A restart during draining is refused as busy.

Copy reusable modules into mcp_server during development; at cutover delete rpc_server completely, `src/freecad_mcp/` completely and its console entry point. Search `rpc_server|freecad_mcp|Start_RPC_Server|Stop_RPC_Server|auto_start_rpc|xmlrpc` across addon, tests, examples, pyproject.toml and .github to migrate every remaining executable consumer. No aliases or bridge remain. Existing parts-library outcomes are accessible through run_script; no dedicated client-dependent examples survive.

Set pyproject project name freecad-mcp-addon, version 2.0.0, requires-python >=3.11, dependencies=[], dev dependency pytest only; remove project.scripts. Explicitly configure Hatch wheel packages=["addon/FreeCADMCP"] and sdist inclusion of addon, tests and package metadata instead of implicit discovery of the deleted client package. FreeCAD installation remains copying/symlinking the FreeCADMCP directory into its Mod directory, not pip installing into bundled Python. Align .python-version with 3.11 and regenerate uv.lock as part of this dependency cutover.

Retarget test_gui_dispatch.py and test_dispatch_health.py imports/contract together with their implementation. Preserve the Invalid/Error/Touched and valid-shapeless-object cases in test_object_validation.py, adapting them to atomic behavior. Remove XML-RPC-only test_rpc_handlers.py/test_rpc_concurrency.py and serializer/parts-library tests tied solely to deleted APIs after replacement behavior checks exist. Do not keep obsolete assertions through shims. CI uses Python 3.11/3.12/3.13, compiles addon (not src), runs pytest and uv lock --check, and replaces the CLI/SDK compatibility job with addon wheel-content verification. Runtime verification below is separate from stubbed CI and cannot be claimed from it.

## Assumptions & contingencies

- User-overridable deployment choice: loopback-only bearer access; no remote listener/TLS/CORS configuration. Arbitrary scripts possess full FreeCAD-user authority.
- Tasks, script namespaces and consent nonces are in-memory and survive client disconnects, not server restart/FreeCAD crash. Consent signatures intentionally expire on restart.
- FreeCAD 1.1 maintenance patches >=1.1.3 are supported; 1.2 and older releases fail startup rather than selecting fallback APIs. If a required core API contradicts the disposable runtime probe, fail the affected feature explicitly and record the prerequisite; do not add version-probing aliases. Missing FEM prerequisites disable FEM execution only, not document/modeling operations.
- The modern solver choice intentionally corrects the original factory/pipeline mismatch. Existing legacy-solver analyses receive an explicit error instead of an implicit conversion that could change an engineering model.
